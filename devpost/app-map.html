What this app is

Caddie is an agent steward for hackathons. You type in chat; an LLM with server-side tools searches Devpost, reads rules with citations, scores fit, writes your plan docs, creates a GitHub repo, judges your work, and keeps a task list. The left pane (The Card + Tasks) is the brief; the right pane is the channel.

Four pieces: routes (one shell route + one chat API route), tools (the model's hands), D1 (SQLite — profile, contests, claims, cards, docs, repos, tasks, messages), and external truth (Parallel Search/Extract, Gemini, GitHub REST).

Reference route (3 stops)

  1. The shell owns everything — src/routes/index.tsx, function Shell. The route loader calls getBootstrap (server fn in src/server/data.ts) which reads profile, messages, card items, plan docs, and tasks from D1. The resizable split lives here too.
  2. The agent and its tools — src/routes/api/chat.ts, the tools object inside the POST handler. Eleven spec tools; each execute does real side effects via src/server/ modules (parallel.ts, github.ts, judge.ts, recheck.ts, taskRunner.ts). The system prompt (profile briefing + tooling rules) is built right above it.
  3. Memory and honesty — src/server/db.ts. Every claim row carries source_url; every card write goes through setCardItems (this is where the bind-count bug lived and got caught). Time display rules live in src/lib/format.ts: unknown renders as —, never a plausible number.

To change this, start here

  • Voice / briefing of the caddie → src/lib/llm.ts (CADDIE_SYSTEM) and the system-prompt block in src/routes/api/chat.ts.
  • Card content or a new card type → the tool that writes it in chat.ts + render map in src/components/TheCard.tsx.
  • Add a tool → add a tool({...}) entry in chat.ts, a server module in src/server/, a banner renderer in src/components/ToolBanners.tsx.
  • Colors / typography → @theme block in src/styles/halo.css.
  • Schema → migrations/0001_init.sql, then bun run db:migrate.

A practice to reuse

Trap the real error; never trust a masked one. The GitHub tool failed as "An error occurred." from the AI SDK. Wrapping the tool's execute to return the raw error exposed HTTP 403; a curl probe with the identical token succeeded, isolating the difference to a missing User-Agent header (GitHub rejects agent-less requests). The same move had already caught a D1_ERROR: Wrong number of parameter bindings in setCardItems.

Reusable on any project: when a framework sanitizes failures, make the boundary return the raw cause (try/catch → {failed, detail}), then bisect with the smallest probe that bypasses the framework. Both bugs were found in minutes because the tool result carried the true error instead of a shrug.

Run it again

bun install · bun run db:migrate · bun run dev → open http://localhost:3000. Keys live in .dev.vars (gitignored): AI_PROVIDER=google, LLM_API_KEY, PARALLEL_API_KEY, GITHUB_TOKEN. Cron path (optional): bun run build, then wrangler dev -c wrangler.cron.jsonc --test-scheduled and curl /__scheduled.
